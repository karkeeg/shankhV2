# Production-ready learning content set for Shankh

## Executive summary

Shankh should launch as an integrated, case-first learning system rather than as three disconnected tabs. The March 2026 product deck defines the core experience as a multi-interface workspace spanning spreadsheet, decision canvas and simulation, with immediate AI feedback and measurable skill scoring; the product concept narrows Phase 1 to short lessons, interactive exercises, simulations, user scoring and admin authoring, with an initial emphasis on pharma and biotech investment analysis; and the casebook emphasises a disciplined solve pattern of clarify, structure, analyse and conclude across profitability, market entry, pricing, growth and due-diligence cases. Quantus, meanwhile, demonstrates the public-market UX primitives that are already working: guided study paths, adjustable difficulty, structured progress, “Check Answer”, detailed hints and formula guidance, and an AI learning assistant. The production recommendation below therefore makes every module run through a consistent sequence: lesson panel, MCQ warm-up, Quantus task set, Canvas task set, final decision, AI debrief, skill update. fileciteturn0file0 fileciteturn0file1 fileciteturn0file2 citeturn1view0turn1view1turn1view2turn11view0turn11view1

## Evidence base and design principles

This design uses four evidence streams. First, the uploaded Shankh materials define the product strategy, user journey, three-panel UI blueprint, skill scoring and phased delivery. Secondly, the uploaded casebook from entity["organization","IIM Ahmedabad","management school india"] provides the intellectual grammar for case-solving: good clarifying questions, non-mechanical framework use, issue trees, and the main case families that should drive Canvas and judgement design. Thirdly, the public Quantus surface and indexed practice pages show how a spreadsheet-first training product presents study paths, difficulty levels, instructions/context, answer validation, hints, progress tracking and an AI assistant. Fourthly, official pharma and biotech data sources provide the right long-term evidence layer for market sizing, diligence and valuation cases. Exact Shankh authoring APIs, formula-evaluator APIs, LLM orchestration internals and warehouse schemas are unspecified, so the report below treats them as implementation details to be mapped later. fileciteturn0file0 fileciteturn0file1 fileciteturn0file2 citeturn12view0turn1view1turn1view2turn11view0turn11view1

The design principles that follow are straightforward. One case context should persist across all three workspaces inside a module. Guidance should be progressive rather than binary: first a hint, then a warning, then a targeted explanation. Spreadsheet tasks should validate both arithmetic and formula logic. Canvas tasks should score semantic equivalence, not only exact labels. Final decisions should always ask for a recommendation, not merely a calculation. And progress should roll up into skill tags rather than into a single opaque score. Those principles fit the Shankh deck’s problem-first approach and the casebook’s insistence that frameworks are tools for structured thinking rather than scripts to be recited. fileciteturn0file0 fileciteturn0file1

## Final app structure and navigation

The private Quantus dashboard route publicly exposes a minimal signed-in shell with Dashboard, Learn, Profile and Contact, while the public learning taxonomy exposes grouped paths for Financial Statements, Financial Analysis, Financial Modelling, Investment Banking and Private Equity. Shankh should keep the same top-shell simplicity, but replace “Contact” with “Progress” and make the three workspaces the centre of the information architecture. The result is a shallower shell and a deeper module system. citeturn12view0turn1view1

### Introduction to Assets

**Learning objective.** Distinguish current from non-current assets, build asset subtotals correctly, and connect classification to liquidity.  
**Case context.** A small distribution company is preparing an opening balance-sheet training file after its first full operating quarter.

**MCQs**

| Question | Options | Correct answer | Short rationale |
|---|---|---|---|
| Which item is ordinarily a current asset? | A Factory building; B Cash; C Patent; D Long-term loan receivable due in 5 years | B | Cash is available within the operating cycle and supports near-term liquidity. |
| Accounts receivable refers to | A Money owed to suppliers; B Money owed by customers; C Future tax expense; D Owner’s capital | B | Receivables arise when the company records sales before collecting cash. |
| Inventory is usually classified as current because it is | A Always cash; B Sold or used within one operating cycle; C A financing source; D Exempt from valuation | B | Inventory is expected to convert into sales or production use in the near term. |
| Which item belongs in non-current assets? | A Cash; B Inventory; C Land; D Trade receivables | C | Land is a long-lived asset, not expected to convert to cash within a year. |
| If inventory rises while sales are flat, the most likely near-term effect is | A More cash tied up; B Lower assets; C Higher equity automatically; D Lower current assets | A | Extra stock usually absorbs cash rather than releasing it. |

**Quantus tasks**

| Task | Inputs | Expected formula | Expected answer | Accepted formula variants | Difficulty |
|---|---|---|---|---|---|
| Calculate total current assets | Cash ₹12,000; Accounts receivable ₹15,000; Inventory ₹8,000 | `cash + ar + inventory` | ₹35,000 | `=SUM(B2:B4)`; `=B2+B3+B4`; `=cash+ar+inventory` | Easy |
| Calculate total non-current assets | PPE ₹50,000; Patents ₹10,000; Long-term investments ₹12,000 | `ppe + patents + lti` | ₹72,000 | `=SUM(B6:B8)`; `=B6+B7+B8`; `=ppe+patents+lti` | Easy |
| Calculate total assets | Current assets ₹35,000; Non-current assets ₹72,000 | `current_assets + non_current_assets` | ₹107,000 | `=B5+B9`; `=current_assets+non_current_assets` | Easy |

**Canvas tasks**

| Task | Expected structure or answer | Scoring rubric |
|---|---|---|
| Drag asset cards into Current Assets and Non-current Assets buckets | Current: Cash, Accounts receivable, Inventory. Non-current: Land, Machinery, Patent, Long-term investment. | 12 pts: 6 correct placement, 3 completeness, 2 logic, 1 clarity |
| Build the asset-side hierarchy | Assets → Current Assets → Cash / AR / Inventory; Assets → Non-current Assets → PPE / Intangibles / Long-term investments; show both subtotals and total assets | 13 pts: 5 correct hierarchy, 4 correct subtotals, 3 completeness, 1 clarity |

**Final decision prompt**

A CFO needs to improve short-term liquidity this quarter with the least strategic disruption. Which action should come first?  
A Collect receivables faster and reduce slow-moving inventory  
B Buy additional machinery  
C Increase dividends  
D Prepay long-term lease liabilities  

**Scoring.** 15 pts for A with liquidity rationale; 9 pts for A without rationale; 3 pts for D if the answer notes obligation reduction but ignores timing; 0 otherwise.

**AI coach snippets**

| Hint | Warning | Correct feedback | Incorrect feedback |
|---|---|---|---|
| “Only include items expected to turn into cash or be used within the operating cycle.” | “You have likely included a non-current item inside a current subtotal.” | “Correct: the subtotal includes only near-term operating assets.” | “Re-check classification before summing; the math may be right on the wrong items.” |

### Balance Sheet Classification

**Learning objective.** Understand how assets, liabilities and equity connect through the balance-sheet identity and financing maturity.  
**Case context.** A light manufacturing business is financing new machinery and must present a clean opening balance sheet.

**MCQs**

| Question | Options | Correct answer | Short rationale |
|---|---|---|---|
| The balance-sheet identity is | A Revenue = Cost + Profit; B Assets = Liabilities + Equity; C Cash = Profit + Debt; D Assets = Equity – Liabilities | B | This is the core accounting identity. |
| Trade payables are normally classified as | A Asset; B Revenue; C Liability; D Equity | C | Payables are obligations owed to suppliers. |
| Retained earnings belong to | A Current liabilities; B Equity; C Revenue; D Inventory | B | Retained earnings accumulate profits kept in the business. |
| If assets are ₹125,000 and liabilities are ₹80,000, equity is | A ₹45,000; B ₹80,000; C ₹125,000; D ₹205,000 | A | Equity is the residual after liabilities are deducted from assets. |
| A 3-year term loan is usually a | A Current asset; B Current liability; C Non-current liability; D Equity reserve | C | The maturity is beyond the short-term current period. |

**Quantus tasks**

| Task | Inputs | Expected formula | Expected answer | Accepted formula variants | Difficulty |
|---|---|---|---|---|---|
| Calculate total assets | Cash ₹10,000; Inventory ₹20,000; PPE ₹70,000 | `cash + inventory + ppe` | ₹100,000 | `=SUM(B2:B4)`; `=cash+inventory+ppe` | Easy |
| Calculate total liabilities | Accounts payable ₹15,000; Short-term debt ₹10,000; Long-term debt ₹35,000 | `ap + std + ltd` | ₹60,000 | `=SUM(B6:B8)`; `=ap+std+ltd` | Easy |
| Calculate equity | Assets ₹100,000; Liabilities ₹60,000 | `assets - liabilities` | ₹40,000 | `=B5-B9`; `=assets-liabilities` | Easy |

**Canvas tasks**

| Task | Expected structure or answer | Scoring rubric |
|---|---|---|
| Sort accounts into Assets, Liabilities and Equity | Assets: Cash, Inventory, PPE. Liabilities: AP, ST debt, LT debt. Equity: Share capital, Retained earnings. | 12 pts: 6 correct sorting, 3 completeness, 2 logic, 1 clarity |
| Build financing maturity map | Assets matched against current liabilities, non-current liabilities and equity; long-lived machinery should not be funded mainly with short-term sources | 13 pts: 5 correct maturity logic, 4 correct categories, 3 recommendation logic, 1 clarity |

**Final decision prompt**

The company wants to buy machinery that will be used for five years while preserving its current ratio. Which financing choice is strongest?  
A Short-term debt  
B Long-term debt or equity  
C Record the machinery directly as an expense  
D Put the machinery under inventory  

**Scoring.** 15 pts for B with maturity-matching rationale; 9 pts for B without rationale; 3 pts for A if liquidity trade-off is at least recognised; 0 otherwise.

### Income Statement Flow

**Learning objective.** Trace how revenue flows through COGS, operating expenses, interest and tax to net income.  
**Case context.** A regional packaged-food company is explaining why profit has changed despite higher sales.

**MCQs**

| Question | Options | Correct answer | Short rationale |
|---|---|---|---|
| Gross profit equals | A Revenue – COGS; B Revenue – Tax; C EBITDA – Interest; D Cash – Debt | A | Gross profit captures revenue after direct production costs. |
| EBITDA excludes | A Revenue; B COGS; C Depreciation and amortisation; D SG&A | C | EBITDA is before D&A, interest and tax. |
| Interest expense appears below | A Revenue only; B EBIT; C Inventory; D Gross margin | B | Interest is financing cost, not an operating cost. |
| If revenue rises but gross profit barely changes, the most likely issue is | A Higher COGS pressure; B Lower cash only; C Higher equity; D Lower asset turnover automatically | A | Weak gross profit conversion typically signals direct-cost pressure. |
| The final profit line after tax is | A EBITDA; B EBIT; C Net income; D Gross profit | C | Net income is the bottom line after interest and tax. |

**Quantus tasks**

| Task | Inputs | Expected formula | Expected answer | Accepted formula variants | Difficulty |
|---|---|---|---|---|---|
| Calculate gross profit and gross margin | Revenue ₹250; COGS ₹150 | `revenue - cogs`; `(revenue - cogs) / revenue` | ₹100; 40% | `=B2-B3`; `=(B2-B3)/B2`; `=1-B3/B2` | Easy |
| Calculate EBITDA | Gross profit ₹100; Operating expenses ₹55 | `gross_profit - opex` | ₹45 | `=B4-B5`; `=gross_profit-opex` | Medium |
| Calculate net income | EBITDA ₹45; D&A ₹10; Interest ₹5; Tax ₹8 | `ebitda - da - interest - tax` | ₹22 | `=B6-B7-B8-B9`; `=ebitda-da-interest-tax` | Medium |

**Canvas tasks**

| Task | Expected structure or answer | Scoring rubric |
|---|---|---|
| Arrange the income-statement flow | Revenue → COGS → Gross Profit → Operating Expenses → EBITDA → D&A → EBIT → Interest → Profit Before Tax → Tax → Net Income | 12 pts: 6 correct order, 3 completeness, 2 logic, 1 clarity |
| Build a diagnostic bridge for falling net income | Revenue, direct costs, opex, D&A, interest, tax; show where margin compression occurs and which line should be investigated first | 13 pts: 5 correct bridge structure, 4 identification of likely driver, 3 prioritisation, 1 clarity |

**Final decision prompt**

Revenue grew 10%, gross profit grew 8%, but EBITDA fell 5%. What should management review first?  
A Lower tax rate assumptions  
B SG&A and operating leverage  
C Share count  
D Historical depreciation policy only  

**Scoring.** 15 pts for B with operating-cost rationale; 9 pts for B without rationale; 3 pts for D if the answer at least notes below-EBIT effects; 0 otherwise.

|---|---|---|---|
| “Move line by line from top to bottom before jumping to the answer.” | “You may be mixing operating cost with financing cost.” | “Correct: you tracked the statement in the right sequence.” | “Revisit which costs belong above and below EBITDA.” |

### Margin Analysis

**Case context.** A restaurant chain is defending a pricing campaign while profitability weakens.

**MCQs**

| Question | Options | Correct answer | Short rationale |
|---|---|---|---|
| Gross margin is | A Gross profit / Revenue; B Net income / Revenue; C EBITDA / Assets; D Revenue / COGS | A | Gross margin measures direct profitability against revenue. |
| EBITDA margin shows | A Operating profitability before D&A, interest and tax; B Total assets used; C Only free cash flow; D Market share | A | It isolates operating performance before non-cash and financing effects. |
| Net margin should use which denominator? | A Revenue; B COGS; C Equity; D Debt | A | Margin ratios are typically profit divided by revenue. |
| If gross margin is stable but EBITDA margin falls, the likely problem is | A SG&A or overhead creep; B Inventory revaluation only; C Lower tax rate; D Higher share capital | A | Stable gross profit with weaker EBITDA points to operating expense pressure. |
| Higher fixed costs typically make margins | A Less sensitive to volume; B More sensitive to volume; C Equal to gross profit; D Immune to pricing | B | Operating leverage increases sensitivity to changes in sales. |

### Working Capital

**Learning objective.** Compute NWC, current ratio and cash-conversion-cycle thinking.  
**Case context.** An electronics wholesaler wants to release cash without hurting service levels.

**MCQs**

| Question | Options | Correct answer | Short rationale |
|---|---|---|---|

| Current ratio equals | A Current assets / current liabilities; B Revenue / assets; C Assets / equity; D Cash / debt | A | It is the classic short-term coverage ratio. |
| DSO mainly measures | A Collection speed; B Inventory quality; C Interest burden; D Tax efficiency | A | It tracks how long customers take to pay. |
| Higher DPO generally means | A More supplier financing; B Faster collections; C Lower debt; D Higher capital expenditure | A | Paying later temporarily preserves cash. |
| Cash conversion cycle equals | A DIO + DSO – DPO; B DIO – DSO + DPO; C DSO / DPO; D Revenue / NWC | A | It measures days cash is tied up in operations. |

| Calculate cash conversion cycle | DIO 50; DSO 35; DPO 30 | `dio + dso - dpo` | 55 days | `=B11+B12-B13`; `=dio+dso-dpo` | Medium |

## Scoring architecture and skill tags

The deck and concept note make skill scoring a core product requirement, while Quantus’s public surface shows progress tracking, difficulty levels and answer validation. The scoring model should therefore be granular enough to diagnose skills, but simple enough for learners to understand at a glance. The cleanest production model is a 100-point module score with item-level tags rolling into module, category and workspace mastery. fileciteturn0file0 fileciteturn0file2 citeturn1view0turn1view2

### Independence score

Mastery should not be heavily penalised for using help. Instead, maintain a separate **Independence Score** out of 100 using hint count, failed checks and elapsed time bands. This avoids punishing learners for seeking guidance while still preserving useful coaching signals.

| Signal | Suggested effect on Independence Score |
|---|---:|
| No hints used | +10 |
| 1–2 hints used | +5 |
| 3+ hints used | 0 |
| 0–1 failed checks per task | +10 |
| 2–3 failed checks per task | +5 |
| 4+ failed checks per task | 0 |

## UI and UX integration with AI coach and analytics

The screenshots you supplied and the public Quantus practice pages point to the right operating pattern: instructions and context must stay visible; the centre panel must stay clean; and the right rail must support both guidance and answer review. Quantus also explicitly markets limited or unlimited “Check Answer”, detailed hints, formula guidance and progress tracking, which makes those patterns safe to borrow for Shankh’s spreadsheet workspace. The Shankh blueprint extends that logic by adding a richer intelligence panel with decision audit, KPI radar, learning hints and scenario forks. citeturn11view0turn11view1turn1view2 fileciteturn0file0

### Recommended right-rail design

| Tab | Purpose | When shown | What it contains |
|---|---|---|---|
| AI Coach | Live guidance during work | Default during attempt | Hint, warning, concept recap, next-step suggestion |
| Result | Validation after check | After user clicks Check Answer | Correct/incorrect status, targeted explanation, missed cells or branches |
| Skill View | Reflection and motivation | After activity completion | Skill tags affected, score delta, recommended next module |

### Hint timing

| Trigger | Recommendation |
|---|---|
| 60–90 seconds of inactivity on an active task | Show one low-intrusion hint nudge |
| First failed spreadsheet check | Show one conceptual hint only |
| Second failed spreadsheet check | Show one procedural hint plus highlight the impacted section |
| Third failed spreadsheet check | Show precise explanation, but do not auto-fill the answer |
| Canvas submission below threshold | Show branch-level critique and one “best next edit” instruction |
| Final decision wrong | Show strongest missing consideration, not the full answer immediately |

### Check-answer flow

| Step | Behaviour |
|---|---|
| User clicks Check Answer | Freeze current task state, validate formulas and outputs, log attempt |
| If correct | Show concise success message, unlock next task, update score immediately |
| If partially correct | Highlight the affected cells or branches, keep the correct parts locked in place, show one targeted explanation |
| If incorrect | Keep the user in the task, open AI Coach warning, allow retry without losing correct prior work |
| After activity completion | Show score contribution, skill tags updated, and recommendation for the next module |

### Analytics events

| Event name | Fired when | Minimum payload |
|---|---|---|
| `module_viewed` | Module page loads | moduleSlug, stage, sessionId |
| `lesson_completed` | User scrolls through or acknowledges lesson | moduleSlug, dwellSeconds |
| `mcq_answered` | MCQ submitted | itemId, selectedOption, correct, elapsedSeconds |
| `quantus_check_answer` | Spreadsheet validation clicked | itemId, attemptNo, correct, hintCount, elapsedSeconds |
| `quantus_formula_flagged` | Formula logic wrong though value may match | itemId, formulaType, attemptNo |
| `canvas_submitted` | Canvas scoring triggered | itemId, score, hintCount, elapsedSeconds |
| `decision_submitted` | Final recommendation submitted | itemId, selectedOption, score |
| `ai_hint_opened` | User manually opens hint | itemId, hintTier |
| `ai_feedback_shown` | Coach message displayed automatically | itemId, feedbackType |
| `module_completed` | Entire module completed | moduleSlug, totalScore, independenceScore, passStatus |

### Sample concise AI feedback for common wrong answers

| Wrong-answer pattern | Sample feedback |
|---|---|
| Non-current item included in current subtotal | “You have included a long-lived asset in a current subtotal. Re-check classification before summing.” |
| Margin denominator wrong | “Margin should be divided by revenue, not by cost.” |
| Receivables sign wrong in CFO | “Receivables up means cash down. Reverse the sign on the working-capital adjustment.” |
| Market sizing order wrong | “Do not apply price until you have reduced the population to treated patients.” |
| Entry mode too aggressive | “Your recommendation assumes capabilities the firm does not yet have. Revisit mode selection.” |
| Valuation skips profitability conversion | “You applied the multiple to revenue directly. Convert to EBITDA or the chosen profit base first.” |
