CORRECTED 5-LEVEL HIERARCHY
================================================================================

Level 1: MODULE        — Finance | Strategy | Operations
Level 2: TOPIC         — Core Concepts | DCF | Trading Comps | LBO | M&A | Simulation
Level 3: SUBTOPIC      — EV vs Equity | Capital Structure | Share Count & Dilution | ...
Level 4: LESSON        — Lesson 1 · Definition (Easy) | Lesson 2 · Bridge (Medium) | ...
Level 5: ACTIVITY      — MCQ | Canvas | Quantus (1–3 per lesson)

NOTES:
- "Module" and "Learning Plan" are the SAME concept. No separate learning_plans table.
- "Topic" is what was previously called "Learning Plan" (e.g. Core Concepts, DCF).
- "Subtopic" is what was previously called "Topic" (e.g. EV vs Equity Value).
- Lesson contains 1–3 activity types based on difficulty.
- The old learning_plans table is REMOVED entirely.

HIERARCHY EXAMPLE:
  Module: Finance
    Topic: Core Concepts
      Subtopic: Enterprise Value vs Equity Value (type: topic)
        Lesson 1 [Easy]   → MCQ only
        Lesson 2 [Medium] → MCQ + Canvas
        Lesson 3 [Hard]   → MCQ + Canvas + Quantus
      Subtopic: Capital Structure (type: topic)
        Lesson 1 / 2 / 3
      Subtopic: MCQ Set (type: drill)
        Lesson 1 [Easy]   → MCQ only
      Subtopic: Quant Lab (type: drill)
        Lesson 1 [Hard]   → Quantus only
    Topic: DCF Valuation
      Subtopic: Free Cash Flow
      Subtopic: Discount Rates
      Subtopic: Terminal Value
    Topic: Trading Comps
    Topic: Transaction Comps
    Topic: LBO
    Topic: M&A
    Topic: Simulation

SECTION 1: ENUM TYPES
================================================================================

activity_type   ENUM — 'mcq' | 'quantus' | 'canvas'
  Used on: lesson_activities, activity_hints, canvas_activities.subtype,
           user_activity_drafts, skill_bundle_items, user_mcq_sessions,
           user_canvas_sessions, user_quantus_sessions

cell_type       ENUM — 'editable' | 'formula' | 'prefilled' | 'empty' | 'header'
  Used on: quantus_cells.cell_type
  editable  = yellow cell; user inputs value
  formula   = auto-computed from formula_expression (client-side); not user-editable
  prefilled = historical/given data (shown in blue); read-only
  empty     = blank cell with no interaction
  header    = row/column label cell (not a data cell)

cell_style      ENUM — 'default' | 'yellow' | 'blue' | 'bold' | 'gray' | 'green'
  Used on: quantus_cells.style_class (visual rendering hint)

difficulty      ENUM — 'easy' | 'medium' | 'hard'
  Used on: lessons.difficulty
  easy   = MCQ only (1 activity)
  medium = MCQ + Canvas (2 activities)
  hard   = MCQ + Canvas + Quantus (3 activities)
  Custom lessons may override the default activity count via lesson_activities.

lesson_status   ENUM — 'not_started' | 'in_progress' | 'completed'
  Used on: user_lesson_progress.status

subtopic_type   ENUM — 'topic' | 'drill'
  Used on: subtopics.type
  topic = standard learning subtopic with lessons
  drill = standalone practice set (MCQ drill, Quant lab)

canvas_subtype  ENUM — 'drag_drop' | 'freeform'
  Used on: canvas_activities.subtype
  drag_drop = cards dragged into labelled zones; auto-scored
  freeform  = blank drawing canvas; user draws flowchart/diagram

session_status  ENUM — 'active' | 'completed' | 'abandoned'
  Used on: user_lesson_sessions.status

SECTION 8: PROGRESS TABLES (4 Levels)
================================================================================

All progress tables share these design principles:
  1. Cached — updated by cascade after every session submit
  2. Per-user — every table has UNIQUE(user_id, content_id)
  3. Scores use GREATEST() — never go backwards
  4. Percentages stored as NUMERIC(5,2) — 0.00 to 100.00
  5. Three metric scores per level: recall_strength, concept_accuracy, application_score

────────────────────────────────────────────────────────────────────────────────
TABLE: user_lesson_progress
PURPOSE: Per-user, per-lesson progress cache. Most granular level.
         Tracks completion %, best scores per activity type, and current status.
────────────────────────────────────────────────────────────────────────────────
Column                Type                    Constraints         Description
──────────────────────────────────────────────────────────────────────────────
id                    UUID                    PK, DEFAULT uuid()
user_id               UUID                    NOT NULL FK→users(id) CASCADE
lesson_id             UUID                    NOT NULL FK→lessons(id) CASCADE
lesson_completion_pct NUMERIC(5,2)            NOT NULL DEFAULT 0   0–100
                                                            = (activity types with ≥1 session / total assigned) × 100
mcq_best_score        NUMERIC(5,2)                                NULL if no MCQ assigned or not attempted
                                                            = best score_pct from user_mcq_sessions for this lesson
canvas_best_score     NUMERIC(5,2)                                NULL if no canvas assigned or not attempted
quantus_attempted     BOOLEAN                 NOT NULL DEFAULT FALSE  TRUE after first quantus session
status                lesson_status           NOT NULL DEFAULT 'not_started'
hints_used            INT                     NOT NULL DEFAULT 0   Total hints revealed across all activities
started_at            TIMESTAMPTZ                                 Set on first activity attempt
completed_at          TIMESTAMPTZ                                 Set when lesson_completion_pct = 100
updated_at            TIMESTAMPTZ             NOT NULL DEFAULT now()

CONSTRAINTS:
  uq_ulp UNIQUE (user_id, lesson_id)

INDEXES:
  idx_ulp_user    ON user_lesson_progress(user_id)
  idx_ulp_lesson  ON user_lesson_progress(lesson_id)
  idx_ulp_status  ON user_lesson_progress(user_id, status)

────────────────────────────────────────────────────────────────────────────────
TABLE: user_subtopic_progress
PURPOSE: Cached rollup per (user, subtopic). Computed as average of lessons.
────────────────────────────────────────────────────────────────────────────────
Column                    Type                    Constraints         Description
──────────────────────────────────────────────────────────────────────────────

SECTION 15: PROGRESS CASCADE — 8-STEP SERIALIZABLE TRANSACTION
================================================================================

Triggered by: POST /me/sessions/mcq  |  /me/sessions/canvas  |  /me/sessions/quantus

Step 1: INSERT completed session row + answers/placements/snapshot

Step 2: UPSERT user_lesson_progress
  mcq_best_score    = GREATEST(existing, new_score_pct)
  canvas_best_score = GREATEST(existing, new_score_pct)
  quantus_attempted = TRUE (once set, never false)
  hints_used       += session.hints_used
  lesson_completion_pct = (activity types with ≥1 session / total assigned) × 100
  status = 'completed' if pct=100, 'in_progress' if pct>0, 'not_started' otherwise
  completed_at = now() if newly completed

Step 3: UPSERT user_subtopic_progress
  subtopic_completion_pct = AVG(lesson_completion_pct) for all lessons in subtopic
  recall_strength         = AVG(mcq_best_score) for lessons in subtopic
  concept_accuracy        = AVG(canvas_best_score) for lessons in subtopic
  application_score       = (quantus_attempted_count / quantus_lesson_count) × 100
  lessons_completed       = COUNT(status='completed')

Step 4: UPSERT user_topic_progress
  topic_completion_pct = AVG(subtopic_completion_pct)
  [metrics aggregated from subtopics]

Step 5: UPSERT user_module_progress
  module_completion_pct = AVG(topic_completion_pct)
  [metrics aggregated from topics]

Step 6: UPDATE user_lesson_sessions
  last_active_at = now()
  status = 'completed' if lesson_completion_pct = 100

Step 7: DELETE user_activity_drafts WHERE (user_id, activity_id, activity_type)
  Draft is cleared atomically with the session submit.

Step 8 (conditional): IF activity is in a skill_bundle_item:
  UPSERT user_skill_item_progress
    best_score_pct = GREATEST(existing, new_score)
    is_completed   = TRUE
    attempts      += 1
  UPDATE user_skill_bundle_progress
    items_completed = COUNT(is_completed = TRUE)
    completion_pct  = items_completed / items_total × 100

COMMIT — All 8 steps atomic. Full rollback on any failure.

DRAFT AUTO-SAVE (separate lightweight transaction, runs every ~1.5s):
  UPSERT user_activity_drafts (draft_state, last_saved_at)
  UPDATE user_lesson_sessions SET last_active_at = now()
  COMMIT — READ COMMITTED isolation (not SERIALIZABLE)

── CONTENT READ ──────────────────────────────────────────────────────────────

GET  /api/v1/modules
     Returns all active modules with user's module_completion_pct + 3 metrics

GET  /api/v1/modules/:id/topics
     Returns topics in module with topic_completion_pct + metrics + subtopics_total

GET  /api/v1/topics/:id
     Returns topic detail + user topic-level progress

GET  /api/v1/topics/:id/subtopics
     Returns subtopics in topic with subtopic_completion_pct + lessons_total + type

GET  /api/v1/subtopics/:id
     Returns subtopic detail + lessons list with difficulty + status

GET  /api/v1/subtopics/:id/lessons
     Returns lessons with: activity_types[], status, lesson_completion_pct,
     mcq_best_score, canvas_best_score, quantus_attempted,
     has_active_session, last_active_at

GET  /api/v1/lessons/:id
     Returns full lesson payload. Only assigned activity objects returned.
     Includes: mcq (null if not assigned), canvas (null), quantus (null).
     Each activity includes: instructions, context, hints_count, full structure.

── LESSON SESSION (Resume) ───────────────────────────────────────────────────

GET  /api/v1/me/resume
     Returns user's most recently active lesson session for dashboard banner.
     Includes: lesson_name, subtopic_name, topic_name, module_name, last_active_at,
               lesson_completion_pct, resume_at_activity

POST /api/v1/me/lessons/:id/session/start
     Start or resume a lesson. Creates user_lesson_sessions if not exists.
     Returns: session_id, is_resume, resume_at { activity_type, draft_exists },
              activities list with completion status and draft_exists per activity.

PATCH /api/v1/me/lessons/:id/session
     Update current activity tab. Called when user switches tabs in lesson.
     Body: { "current_activity_type": "canvas" }

SECTION 17: NO-LOOPHOLE RULES (18 total)
================================================================================

Learning Progress:
  01. GREATEST() on all best_score updates — scores never go backwards
  02. UNIQUE(lesson_id, activity_type) on lesson_activities — no duplicate activity types
  03. UNIQUE INDEX ON mcq_options(question_id) WHERE is_correct=TRUE — exactly one correct option
  04. UNIQUE(user_id, lesson_id) on all 4 progress tables — no duplicate rows
  05. SELECT FOR UPDATE on progress rows during cascade — concurrent session protection
  06. FK CASCADE on all content — deleting lesson deletes activities + sessions
  07. Lesson complete = ALL assigned activity types have ≥1 session (dynamic check)
  08. Soft-delete on content (deleted_at) — preserves session referential integrity
  09. hints_used on every session + user_hint_usage for full audit trail
  10. All progress queries filter by user_id — no cross-user contamination
  11. formula_expression strings never eval()'d server-side — client sandbox only
  12. input_snapshot JSONB written once — append-only history
  13. POST /admin/users/:id/recalculate rebuilds all progress from raw sessions
  14. All 8 steps in ONE SERIALIZABLE transaction — full rollback on any failure

Session / Resume:
  15. UNIQUE(user_id, lesson_id) on user_lesson_sessions — one session per lesson per user
  16. UNIQUE(user_id, activity_id, activity_type) on user_activity_drafts — one draft per activity
  17. Draft DELETE runs atomically in the same transaction as session submit
  18. session.status only moves forward: active → completed (never back)

Skill Building:
  19. GREATEST() in skill item progress — same rule as learning progress
  20. UNIQUE(bundle_id, lesson_id, activity_type) on skill_bundle_items — no duplicate items
